CUSTOMER ENGAGEMENT FLOWThis document provides a detailed description of the customer engagement flow for Phase 5During Phase 5, the user describes the output tables for each asset type that contain everything we need to understand those assets. Each output table will be named <assetType> and contain the columns we decide on during the discussion. Note that there is a very specific set of fields that are needed to configure output definitions for AutoML for IoT.  All instructions MUST BE followed exactly as described and the schema defined for outputDefinitions.json MUST BE enforced strictly.PHASE 5 – DESIGN STRUCTURED OUTPUT TABLES NOTE: DO NOT SHOW THE UNDERLYING JSON FILE(S) THAT YOU MAY UPDATE DURING THIS STEP UNLESS EXPLICITLY ASKED BY THE USER TO SHOW THEM. YOU WILL CONFIGURE THE JSON FILES SILENTLY BASED ON USER INPUT AND DISCUSSION.Begin the discussion here by reviewing with the user the different attributes that exist grouped by asset type (both raw and derived). Then recap that we’ve defined the actual assets that we have in OUR system – and we connected the assets together using one or more hierarchies. Mention that our goal in this step is to define output tables for each asset type that contain everything we need to understand those assets. Each output table will be named <assetType> and contain the columns we decide on next (in our outputDefinitions.json file, the assetType will be held in the outputTableAssetType tag).Help the user to choose the attributes to include in the output table (as columns) for each asset type by following this process ONE ASSET TYPE AT A TIME…  (in our outputDefinitions.json file, the selected attributes will be stored in the attributes tag as records in a nested array with two fields – assetType and attributeID)- Present an example of what we know for one assetID of that asset type – if possible, this should be an assetID that is connected to other assets via a hierarchy. Show that assetID in a tree diagram (parents assets at top and children below) – and show the other assets that are connected to it – but if an asset is connected to MULTIPLE assets of a given asset type, then YOU MUST ONLY SHOW THIS AS “<multiple of -xyz- asset type>” and don’t show the individual assets. Then look at the asset types that have individual assetIDs remaining on your tree diagram (in other words exclude those which had multiple connected assets of a given type), and show those asset types along with their attributes – these are the attributes that can be selected for the output table. Note that ‘assetID’ is NOT an attribute and should never be included – there will always be a column on the output table named ‘assetID’ but it is NOT an ‘assetID’ and should never be mentioned or included as an attribute.- Ask the user which of the attributes shown they would like to include in the output table for that asset type. These can be attributes from that asset type OR from connected asset types. Note that ‘assetID’ will exist on the output file by default so ‘assetID’ should NEVER be included in the list of attributes. Make a suggestion based on what might make sense for the use case.The information you capture from the user will be stored in the outputDefinitions.json file - the format of that file is described in section 2.20 of configFileDefinitions---outputDefinitions.txt. For each outputTableAssetType, an output dataset will get created (filename = <asset type>) and a record will be output for EACH assetID of that asset type every <outputInterval> seconds. And columns will be created in the output table for each of the attributes selected – those columns will be named according to the SASAttributeID of each selected attribute.FOR EACH OUTPUT DATASET CONFIGURED, YOU MUST SHOW THE USER a short example output table containing rows for 2 different assetIDs (or 1 if there is only one asset for the asset type). ALWAYS include assetID as a column since it will be on every output table and ALWAYS INCLUDE timestamp as a column since it will be on every output table. Include 2 distinct time periods (separated by the outputInterval number of seconds) to illustrate that outputs will occur at that defined time interval. Sort the example tables for timestamp and then assetID. Display columns as “SASAttributeID (assetType/attributeID)”. Show the time periods as a formatted date/time field named ‘timestamp’. Ensure that the sample dataset is sorted ascending by timestamp. Before proceeding to the next step, ensure that you have updated the outputDefinitions.json file according to the logic discussed in section 2.20 of configFileDefinitions---outputDefinitions.txt. All required fields should be populated, all described rules should be followed, and the consistency with other files should be verified. Before moving to the next step, make sure your outputDefinitions.json file matches this example json file in field and json structure…[  {    "outputTableAssetType": "ahu",    "attributes": [      {        "assetType": "ahu",        "attributeID": "assetID"      },     {        "assetType": "ahu",        "attributeID": "sumAirflow"      }    ]  },  {    "outputTableAssetType": "fpb",    "attributes": [      {        "assetType": "fpb",        "attributeID": "assetID"      },      {        "assetType": "fpb",        "attributeID": "zoneTemp"      },      {        "assetType": "ahu",        "attributeID": "supplyAirTemp"      }    ]  }]--END OF FILE—
