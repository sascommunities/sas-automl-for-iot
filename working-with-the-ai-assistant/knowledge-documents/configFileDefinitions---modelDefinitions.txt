1. IntroductionThis document defines how to configure and validate the modelDefinitions.json file needed for AutoMLforIoT. This file configures the details needed to describe each machine learning model to be trained and deployed for the user’s AutoML for IoT project.2. Configuration File Schemas, Rules, and ExamplesEach subsection includes Purpose and Considerations, Required Fields, Optional Fields, Validation Rules, Special Notes, and an Example. FOR THE FILES DESCRIBED IN EACH SECTION…* YOU MUST STRICTLY INCLUDE FIELDS THAT ARE REQUIRED* YOU MUST ENSURE THAT NO ADDITIONAL FIELDS ARE INCLUDED BESIDES THOSE THAT ARE DOCUMENTED AS REQUIRED OR OPTIONAL* YOU MUST STRICTLY FOLLOW THE DATA TYPES (STRING OR NUMERIC) FOR EACH FIELD* YOU MUST STRICTLY FOLLOW THE DESCRIPTION OF EACH FIELD* YOU MUST STRICTLY FOLLOW THE VALIDATION RULES AS DESCRIBED * YOU MUST STRICTLY FOLLOW THE EXAMPLE STRUCTURE OF THE JSON FILES-----
2.21 modelDefinitions.json PurposeDefines the high-level information needed to train ML models.Required fields (per model)* targetAssetType (string) – this contains the asset type of the attribute to train a model for. It should contain a valid asset type from the assetTypes json. * targetAttributeID (string) – this contains the attributeID of the attribute to train a model for. It should contain a valid attributeID from the attributes json (for the targetAssetType).* modelGroupLogic (string) – controls whether to train one model per asset, one model to use for all assets, or one model for groups of assets (grouped by the value of another attributeID) – it should contain one of the following values:  o "One Model Per AssetID" – fit one model for each individual assetID  o "One Model Applicable to All Assets" – fit one model to use for all assets  o "One Model Per Unique AttributeID Value" – fit a different model for each unique value of another attributeID. For example, this could be used to fit a different model for each manufacturer or size.* pipelineID (string) – this contains the ID of the pipeline that the user would like to use to train their ML models. The pipelines that exist be default are the following…  o dm.basicintervaltargetpl.template (show as ‘Model Studio – Basic Pipeline)  o dm.intermediateintervaltargetpl.template (show as ‘Model Studio – Intermediate Pipeline)  o dm.advancedintervaltargetpl.template (show as ‘Model Studio – Advanced Pipeline)  o linearRegressionScikit (show as ‘Custom Python – Linear Regression via Scikit Learn’)  o linearRegressionVIYAvScikit (show as ‘Custom Python – Compares several SAS and Scikit Learn approaches’)  o forestSAS (show as ‘Custom SAS - Forest Model’)  o neuralNetworkSAS (show as ‘Custom SAS – Neural Network Model’)* dateRangeStart (string, DDMonYYYY) – this is the start date of the data to use for model training* dateRangeEnd (string, DDMonYYYY) – this is the end date of the data to use for model training* predictorAttributes – this contains a nested array of attribute objects. Each of the attribute objects contains two distinct key-value pairs…   o assetType (string) – the asset type of the attribute - must exist in assetTypes  o attributeID (string) – the attribute to use as a predictor - must exist as a raw or derived attribute for that assetType  o An example of this tag is shown below for 2 attributes…		"predictorAttributes": [		      	{ "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" },			{ "assetType": "combinerBox", "attributeID": "CMBX_temperature_C" }		],If modelGroupLogic = "One Model Per Unique AttributeID Value" then the following field should be specified as well…- modelGroupByAttributeID (string)  - this should contain a valid attributeID for the targetAssetType. Models will be trained for each unique value of that attributeID.Optional fields* modelGroupSubset – users can choose to restrict training to a subset by configuring this tag. If modelGroupLogic=”One Model Per AssetID”, then a user can choose to train models for a specific set of assetIDs by specifying a nested array of { "splitID": "<assetID>" } objects. If modelGroupLogic=”One Model Per Unique AttributeID Value”, then a user can choose to train models for a specific set of values of the selected attributeID by specifying a nested array of { "splitID": "<value of the modelGroupByAttributeID>" } objects.Special Notes:* Discuss models in natural-language logic descriptions (e.g., “predict combiner box current from irradiance and temperature”) only – do not show the underlying json config file.* When choosing analytic models, never use as a predictor attribute an attribute that is largely similar to the target attribute – for example, do not use the rolling average of electrical current to predict electrical current.* A user should not choose as a predictor an assetType/attributeID that could be considered to be ambiguous. For example, an air handler has many connected fan powered boxes – in the air handler output table, they should not request a fan powered box’s attribute since it will not be obvious WHICH fan powered box to obtain the value from.Validation rules* targetAssetType/targetAttributeID must exist in attributes.json or derivedAttributes.json.* Every predictor assetType/attributeID must exist in attributes.json or derivedAttributes.json.* dateRangeStart and dateRangeEnd must be presented DDMonYYYY * dateRangeStart must be less than dateRangeEnd.* If modelGroupLogic = "One Model Per Unique AttributeID Value", then the value specified for modelGroupByAttributeID must exist as a valid attributeID for the targetAssetType in the attributes or derivedAttributes tables.* If modelGroupSubset is specified and modelGroupLogic="One Model Per AssetID" then each splitID must exist as a valid assetID in assets.json.* The structure of this json file MUST ALWAYS STRICTLY FOLLOW the format of the example json shown below…Example[  {    "targetAssetType": "solarFarm",    "targetAttributeID": "totalCurrent",    "modelGroupLogic": "One Model Applicable to All Assets ",    "pipelineID":
