Derived Attribute Type:  codePurpose and ConsiderationsDefines the code logic needed to compute each derived attribute that is defined with an attributeType=”code”. ‘Code’ derived attributes are used to execute logic using one more or more other raw or derived attributes.InstructionsFor derived attributes of type ‘code, you will need to create a record in userDefinedCode.json that describes the logic needed to compute the ‘code’ attribute – this includes valid SAS code as well as a list of the attributes needed for the calculation. A fully-populated json schema for this attribute is shown below…[            {                "SASAttributeID": "currentPerIrradiance",                "logic": "\"\\ncurrentPerIrradiance = current_allStrings / irradiance_poa_myPV\\n\\n\"",              "attributes": [      		 { "assetType": " solarFarm ", "attributeID": "current_allStrings" },  		 { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" }	                  ]            }        ]Here are a few rules to keep in mind when configuring the ‘getValue’ record…- The code stored in the ‘logic’ tag MUST BE valid SAS code – it CANNOT BE Python code or any other language. Since the SAS code will be stored in a json field, you must first surround the SAS code snippet with double quotes, then replace linebreaks with \n, and then escape backslashes and quotes – store the result in the ‘logic’ tag – these changes will ensure that the code is read in properly by AutoML for IoT.- All attributes that are referenced in the SAS code in the ‘logic’ tag MUST BE listed as an attribute (assetType and attributeID) in the ‘attributes’ array.- All variable names used in the SAS code should be the SASAttributeID of those attributes from either the attributes.json or derivedAttributes.json files. Required fields (per item)* SASAttributeID (string) – must match the “SASAttributeID” of a derived attribute in the derivedAttributes json with attributeType=”code”* attributes – this contains a list of the attributes that the calculation depends on. This list is stored as a nested array of attribute objects. Each of the attribute objects contains two distinct key-value pairs…  o assetType (string) – the asset type of the attribute - must exist in assetTypes  o attributeID (string) – the attribute to retrieve the value for - must exist as a raw or derived attribute for that assetType in attributes.json or derivedAttributes.json  o An example of this tag is shown below for 2 attributes…		"attributes": [		      	{ "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" },			{ "assetType": "combinerBox", "attributeID": "CMBX_temperature_C" }		]* logic (string) – this should contain the valid SAS code that is needed to compute the attribute. Since the SAS code will be stored in a json field, you must first surround the SAS code snippet with double quotes, then replace linebreaks with \n, and then escape backslashes and quotes – store the result in the ‘logic’ tag – these changes will ensure that the code is read in properly by AutoML for IoT. The code should expect that if any attributes are listed in the attributes tag, then variables for each of those attributes will already exist with their variable name set to their SASAttributeIDs. One additional variable will also be available by default… outputTimestamp will contain the timestamp in epoch microseconds of the record being output. The code should finish by assigning the value of the new SASAttributeID to the computed value. If the field will be a ‘double’, then this attribute should be set to a numeric value while if it will be a ‘string’, then this attribute should be set to a string value.Validation rules* A record should exist in the derivedAttributes json with SASAttributeID matching this SASAttributeID and attributeType=’code’* The logic tag should contain only valid SAS code – with an assignment contained within the code that assigns a value to the variable named the same as the SASAttributeID. Since the SAS code will be stored in a json field, you must first surround the SAS code snippet with double quotes, then replace linebreaks with \n, and then escape backslashes and quotes – store the result in the ‘logic’ tag – these changes will ensure that the code is read in properly by AutoML for IoT.* YOU MUST DOUBLE-CHECK THAT ALL CODE IN THE LOGIC TAG IS VALID SAS  CODE SYNTAX.* Any attribute mentioned in the SAS code in the ‘logic’ tag MUST BE listed as an attribute in the ‘attributes’ tag.* The assetType/attributeID combinations listed in the attributes objects should be valid attributes in either the attributes json file or derivedAttributes json files.* The structure of this json file MUST ALWAYS STRICTLY FOLLOW the format of the example json shown below…Example[            {                "SASAttributeID": "currentPerIrradiance",                "logic": "\"\\ncurrentPerIrradiance = current_allStrings / irradiance_poa_myPV\\n\\n\"",              "attributes": [      		 { "assetType": " solarFarm ", "attributeID": "current_allStrings" },  		 { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" }	                  ]            }        ]--END OF FILE--
