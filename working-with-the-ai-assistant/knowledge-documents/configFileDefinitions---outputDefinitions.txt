1. IntroductionThis document defines how to configure and validate the outputDefinitions.json file needed for AutoMLforIoT. This file is used to describe the structure and contents of each desired output table desired by the user. Output tables can be generated focused on each asset type, and the columns in each table can contain attributes from that asset type AND/OR from connected asset types. 2. Configuration File Schemas, Rules, and ExamplesEach subsection includes Purpose and Considerations, Required Fields, Optional Fields, Validation Rules, Special Notes, and an Example. FOR THE FILES DESCRIBED IN EACH SECTION…* YOU MUST STRICTLY INCLUDE FIELDS THAT ARE REQUIRED* YOU MUST ENSURE THAT NO ADDITIONAL FIELDS ARE INCLUDED BESIDES THOSE THAT ARE DOCUMENTED AS REQUIRED OR OPTIONAL* YOU MUST STRICTLY FOLLOW THE DATA TYPES (STRING OR NUMERIC) FOR EACH FIELD* YOU MUST STRICTLY FOLLOW THE DESCRIPTION OF EACH FIELD* YOU MUST STRICTLY FOLLOW THE VALIDATION RULES AS DESCRIBED * YOU MUST STRICTLY FOLLOW THE EXAMPLE STRUCTURE OF THE JSON FILES-----
2.20 outputDefinitions.jsonPurposeDefines the structure of the output datasets to be generated. A separate output dataset will be generated for each “outputTableAssetType” specified, and columns will be included in the output datasets for each attribute listed in the attributes tag. Column names in the output datasets will always be the SASAttributeID of the relevant assetType/attributeID. Output datasets will contain one row per timestamp per assetID of the specified assetType, with timestamps separated by ‘outputInterval’ number of seconds.Required fields* outputTableAssetType (string) – an output table will be created for the asset type specified. This must exist in assetTypes.json* attributes – this contains a nested array of attribute objects. Each of the attribute objects contains two distinct key-value pairs…  o assetType (string) – the asset type of the attribute - must exist in assetTypes  o attributeID (string) – the attribute to retrieve the value for - must exist as a raw or derived attribute for that assetType in attributes.json or derivedAttributes.json  o An example of this tag is shown below for 2 attributes…		"attributes": [		      	{ "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" },			{ "assetType": "combinerBox", "attributeID": "CMBX_temperature_C" }		]Optional fields- noneSpecial Notes* When you show the list of user the list of attributes to be included in each output dataset, always show the list of attributes as SASAttributeID (assetType/attributeID).* When you show an example output table for each asset type, always show the column names as the SASAttributeID for each attribute.* Whenever an output definition is discussed, always show both a list of the attributes that will be included in the output table and a short sample dataset. Validation* Attributes list should be non-empty* The attribute list should not contain duplicates per assetType.* All referenced attributes should exist in either attributes or derivedAttributes.* A user should not request an assetType/attributeID that could be considered to be ambiguous. For example, an air handler has many connected fan powered boxes – in the air handler output table, they should not request a fan powered box’s attribute since it will not be obvious WHICH fan powered box to obtain the value from.* The structure of this json file MUST ALWAYS STRICTLY FOLLOW the format of the example json shown below…Example[  {    "outputTableAssetType": "inverter",    "attributes": [      { "assetType": "inverter", "attributeID": "inv_current_sum" },      { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" }    ]  },  {    "outputTableAssetType": "string",    "attributes": [      { "assetType": "string", "attributeID": "current_A" },      { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" },      { "assetType": "combinerBox", "attributeID": "CMBX_temperature_C" }    ]  }]--END OF FILE--
