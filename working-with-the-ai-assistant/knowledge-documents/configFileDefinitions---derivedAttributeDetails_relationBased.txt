Derived Attribute Type:  relationalAggPurpose and ConsiderationsDefines the details needed to compute a ‘relationalAgg’ derived attribute. Attributes of type ‘relationalAgg’ are created to aggregate values of an attribute across connected assets by navigating a named hierarchy.InstructionsFor derived attributes of type ‘relationalAgg’, you will need to create a record in derivedAttributeDetails_relationalAgg.json  that describes the logic needed to compute the ‘relationalAgg’ attribute. A fully-populated json schema for this attribute is shown below…[  {    "assetType": "solarFarm",    "attributeID": "totalCurrent",    "direction": "down",    "hierarchy": "default",    "navigationLogic": "all",    "numLevels": "4",    "summaryLogic": "sum",    "targetAssetType": "string",    "targetAttributeID": "current_A"  }]Here are a few rules to keep in mind when configuring the ‘relationalAgg’ record…- The derived attribute you are creating is denoted by the assetType/attributeID and must have a corresponding record in derivedAttributes.json. This means that this calculation will be made for EACH assetID of that assetType and the new value will be stored as a new attribute attributeID for each assetID of that asset type.- A ‘relationalAgg’ attribute stores the aggregation (min, max, avg, sum) of values for the target attribute (targetAssetType/targetAttributeID) from connected assets that are found by navigating the specified hierarchy. For example, each air handler is connected to multiple fan powered boxes. For air handlers, we may want to calculate the total airflow for all connected fan powered boxes.- ‘summaryLogic’ holds the calculation logic to use – it must be ‘min’, ‘max’, ‘avg’, or ‘sum’- ‘hierarchy’ holds the hierarchyName (from hierarchyList/hierarchyMap) to navigate- ‘direction’ holds the direction (‘up’ or ‘down’) to navigate to find connected assets. ‘up’ navigates only to parent assets while ‘down’ navigates only to child assets- ‘numLevels’ holds the max number of navigation steps to make in the hierarchy (for example, ‘1’ would mean that only directly connected assets would be examined) for the calculation- ‘navigationLogic’ has only two possible options… ‘exact’ instructs the calculation to only aggregate values found that are exactly ‘numLevels’ steps away, while ‘all’ instructs the calculation to aggregate ALL values found while navigating up to ‘numLevels’ steps away.Required fields (per item)* assetType (string) – the assetType of the new attribute. Must be a valid asset type in the assetTypes json.* attributeID (string) – the attributeID of the new attribute. This field should contain only letters, numbers, spaces, underscores, and dashes.* hierarchy (string) – the hierarchy to navigate to find connected assets. Must exist as a ‘hierarchyName’ in hierarchyList.json.* direction (string) – must be "up" or "down" – this is the direction that should be used to search the hierarchy. Up moves from child to parent. Down moves from parent to child.* numLevels (number stored as a string) – max number of levels to traverse from the starting asset (integer >0) – stored as a string* navigationLogic (string) – "all" (include all related assets reached) or “exact” (only include assets found exactly ‘numLevels’ from the asset)* summaryLogic (string) – "sum", "avg", "min", "max" – the type of calculation used to aggregate the values found from the targetAssetType/targetAttributeID* targetAssetType (string) – the asset type from which values are collected. Must be a valid asset type in assetTypes.json.* targetAttributeID (string) – the raw (or derived) attribute to aggregate. The targetAssetType/targetAttributeID must match an assetType/attributeID in either the attributes.json file or derivedAttributes.json file.Optional fields* (none)Validation rules* assetType/attributeID must match a record in derivedAttributes.json with attributeType ‘relationalAgg’* The pair targetAssetType/targetAttributeID must exist either as an assetType/attributeID in the attributes.json or as an assetType/attributeID in the derivedAttributes.json.* hierarchy must exist as a ‘hierarchyName’ in hierarchyList.jsonExample[  {    "assetType": "solarFarm",    "attributeID": "totalCurrent",    "direction": "down",    "hierarchy": "default",    "navigationLogic": "all",    "numLevels": "4",    "summaryLogic": "sum",    "targetAssetType": "string",    "targetAttributeID": "current_A"  }]--END OF FILE--
