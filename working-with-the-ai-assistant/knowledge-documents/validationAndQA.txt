Validation ChecklistThis document describes in detail key rules that MUST BE followed for each configuration file. No exceptions are permitted as any exceptions to the below rules will result in errors.projectInformation.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o projectName (string)  o outputInterval (numeric)  o historyInterval (numeric)* The only other optional fields are the following:  o <none>* projectName ≤ 20 characters* projectName contains letters + numbers only* outputInterval is an integer ≥ 60 seconds* outputInterval is an integer multiple (≥1) of historyInterval-----
assetTypes.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)  o assetTypeLabel (string)* The only other optional fields are the following:  o <none>* Every record includes assetType (string, unique)* Every record includes assetTypeLabel (human-readable string)* No duplicate assetType values-----
attributes.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o SASAttributeID (string)  o attributeType (string)  o dataType (string)   o dataLength (numeric)   o retentionPeriod (numeric)* The only other optional fields are the following:  o dataFormat (string)  o acceptableMin (numeric)  o acceptableMinLogic (string)  o acceptableMax (numeric)  o acceptableMaxLogic (string)* assetType should match an assetType in assetTypes.json* attributeID unique within its assetType* attributeID contains only letters, numbers, spaces, underscores, dashes* SASAttributeID <= 30 characters, valid SAS variable name, unique within assetType* attributeType = "raw"* dataType is either "double" or "string"* dataLength = 8 if dataType="double"* dataLength is a positive integer if dataType="string"* retentionPeriod >= 0* If dataFormat is provided, it must be a valid SAS format* If acceptableMin is set then acceptableMinLogic must be set (“limit” or “missing”)* If acceptableMax is set then acceptableMaxLogic must be set (“limit” or “missing”)-----
assets.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetID (string)   o assetType (string)   o assetLabel (string)* The only other optional fields are the following:  o <none>* Each record includes assetID (unique, valid characters: letters, numbers, spaces, underscores, dashes)* Each record includes assetType (must match an assetType in assetTypes.json)* Each record includes assetLabel (valid characters: letters, numbers, spaces, underscores, dashes)-----

hierarchyList.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o hierarchyName (string)* The only other optional fields are the following:  o <none>* Each record includes hierarchyName (string, unique)* hierarchyName uses valid characters (letters, numbers, underscores, dashes)-----

hierarchyMap.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o hierarchyName (string)   o parent_assetID (string)   o child_assetID (string) * The only other optional fields are the following:  o <none>* Each record includes hierarchyName (must match a hierarchyName in hierarchyList.json)* parent_assetID must match an assetID in assets.json* child_assetID must match an assetID in assets.json-----
staticAttributes.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetID (string)   o attributeID (string)   o value (string)* The only other optional fields are the following:  o <None>* assetID must match an assetID in assets.json* attributeID – you must look up the assetType for each assetID from the assets.json file and then verify that the assetType/attributeID for each record exists in attributes.json* value is stored as a string (even if numeric)-----
historicalData.csv* The file MUST NOT contain a header row – the first line should contain a row of data.* File has either 8 columns per row (opcode, flag, index, category, timestamp, assetID, attributeID, value) if the assets and/or connections will not change dynamically or 18 columns per row (opcode, flag, index, category, timestamp, assetID, attributeID, value, updateAssetAction, updateAssetID, updateAssetType, updateAssetLabel, updateAssetOutputRequired, updateConnectionAction, updateHierarchyName, updateParentAssetID, updateDirection, updateChildAssetID) if the assets and/or connections will be allowed to change dynamically.* opcode must be “I” or “i”* flag must be “N” or “n”* index can contain any integer number* category must be “data”, “updateAssets”, or “updateConnections”  o for most use cases, only records with “data” are needed  o if the assets or connections can change dynamically, then records with “updateAssets” and “updateConnections” may be used as well* timestamp is epoch microseconds* if category=”data”, then assetID, attributeID, and value must be populated* if category=”updateAssets”, then  updateAssetAction, updateAssetID, updateAssetType, updateAssetLabel, and updateAssetOutputRequired must be populated* if category=”updateConnections”, then updateConnectionAction, updateHierarchyName, updateParentAssetID, updateDirection, and updateChildAssetID must be populated* assetID, updateAssetID, updateParentAssetID, and updateChildAssetID - if populated, must match an assetID from the assets.json file* attributeID (if populated) - you must look up the assetType for each assetID from the assets.json file and verify that the assetType/attributeID for each record exists in attributes.json* updateAssetAction, if populated, must contain “add”, “delete”, or “update”* updateAssetType, if populated, must match an assetType in the assetTypes file* updateAssetOutputRequired, if populated, must be “Y” or “N”* updateConnectionAction, if populated, must contain “add”, “delete”, or “update”* updateHierarchyName – if populated, must match a hierarchyName in the hierarchyList file* updateDirection – if populated, must contain one of the following – ‘<--‘, ‘<->’, ‘-->’* File must be sorted in non-decreasing order by timestamp-----
derivedAttributes.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o SASAttributeID (string)   o attributeLabel (string)   o attributeType (string)   o dataType (string)   o dataLength (number) * The only other optional fields are the following:  o dataFormat (string)  o retentionPeriod (numeric)  o acceptableMin (numeric)  o acceptableMinLogic (string)  o acceptableMax (numeric)  o acceptableMaxLogic (string)* assetType must match an assetType from assetTypes.json* attributeID is unique within assetType* assetType/attributeID does not duplicate any assetType/attributeID in attributes.json* SASAttributeID <= 30 chars, valid SAS variable name, unique within assetType* attributeLabel valid characters (letters, numbers, spaces, underscores, dashes)* attributeType is one of: lag, delta, temporalAgg, relationalAgg, countConn, getConn, getAssetID, getAssetLabel, getValue, code* dataType = "double" or "string"* dataLength = 8 if double, positive integer if string* If dataFormat provided then it must be a valid SAS format* retentionPeriod >= 0* If acceptableMin is set then acceptableMinLogic must be set* If acceptableMax is set then acceptableMaxLogic must be set* Every record with attributeType=’code’ must have a corresponding record in userDefinedCode with SASAttributeID matching.* Every assetType/attributeID with attributeType in (lag, delta, temporalAgg, relationalAgg, countConn, getConn, getAssetID, getAssetLabel, getValue) must have a record in the corresponding derivedAttributeDetails_<attributeType>.json file.-----
derivedAttributeDetails_lag.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAttributeID (string)   o EITHER timePeriodNumeric (number stored as a string) OR ALL THREE OF timePeriodAssetType (string), timePeriodAttributeID (string), and maxHistorySeconds (number stored as a string) * Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="lag"* assetType/targetAttributeID must match an assetType/attributeID in attributes.json or match an assetType/attributeID in derivedAttributes.json* If populated, timePeriodNumeric must be an integer multiple of outputInterval* If populated, maxHistorySeconds must be an integer multiple (>0) of outputInterval and timePeriodAssetType/timePeriodAttributeID must match an assetType/attributeID in attributes.json or an assetType/attributeID in derivedAttributes.json-----
derivedAttributeDetails_delta.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAttributeID (string)   o oldTimePeriodNumeric (number stored as a string)  o recentTimePeriodNumeric (number stored as a string)* The only other optional fields are the following:  o <None>* Derived attribute (assetType/attributeID) must match an assetType/attributeID  in derivedAttributes.json with attributeType="delta"* assetType/targetAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json * oldTimePeriodNumeric must be an integer multiple of outputInterval, > 0* recentTimePeriodNumeric must be an integer multiple of outputInterval, >= 0* oldTimePeriodNumeric > recentTimePeriodNumeric------

derivedAttributeDetails_temporalAgg.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAttributeID (string)   o summaryLogic (string)  o EITHER oldTimePeriodNumeric (number stored as a string) OR BOTH oldTimePeriodAssetType (string) and oldTimePeriodAttributeID (string)   o EITHER recentTimePeriodNumeric (number stored as a string) OR BOTH recentTimePeriodAssetType (string) and recentTimePeriodAttributeID (string)   o if any of these fields were used (oldTimePeriodAssetType, oldTimePeriodAttributeID, recentTimePeriodAssetType, recentTimePeriodAttributeID), then maxHistorySeconds (number stored as a string) is also required* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="temporalAgg"* assetType/targetAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* summaryLogic is one of: sum, avg, min, max* If specified, oldTimePeriodNumeric must be an integer multiple of outputInterval and be > 0* If specified, recentTimePeriodNumeric must be an integer multiple of outputInterval and be >= 0* If both oldTimePeriodNumeric and recentTimePeriodNumeric are specified, then oldTimePeriodNumeric > recentTimePeriodNumeric-----
derivedAttributeDetails_relationalAgg.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o hierarchy (string)   o direction (string)  o numLevels (number stored as a string)  o navigationLogic (string)  o summaryLogic (string)  o targetAssetType (string)  o targetAttributeID (string)* The only other optional fields are the following:  o <None>* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="relationalAgg"* hierarchy must match a hierarchyName in hierarchyList.json* direction MUST BE “up” or “down”* numLevels > 0* targetAssetType/targetAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* summaryLogic is one of: sum, avg, min, max* navigationLogic MUST BE ‘exact’ or ‘all’-----
derivedAttributeDetails_getAssetID.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAssetType (string) * The only other optional fields are the following:  o <None>* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="getAssetID"* targetAssetType must match an assetType in assetTypes.json-----
derivedAttributeDetails_getAssetLabel.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAssetType (string) * The only other optional fields are the following:  o <None>* Derived attribute (assetType/attributeID) must match an assetType/attributeID in  derivedAttributes.json with attributeType="getAssetLabel"* targetAssetType must match an assetType in assetTypes.json-----
derivedAttributeDetails_countConn.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o parentsOrChildren (string)  o EITHER hierarchyValue (string) OR hierarchyAttributeID (string)* The only other optional fields are the following:  o subsetAssetType (string)  o queryAssetIDFromThisAttribID (string)* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="countConn"* parentsOrChildren MUST BE “parents” or “children”* Only one of (hierarchyValue OR hierarchyAttributeID) can be provided* If hierarchyValue is populated then it must match a hierarchyName in hierarchyList.json* If hierarchyAttributeID is populated, then assetType/hierarchyAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* If subsetAssetType is provided, then it must match an assetType from assetTypes.json* If queryAssetIDFromThisAttribID is populated, then assetType/ queryAssetIDFromThisAttribID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json-----
derivedAttributeDetails_getConn.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o parentsOrChildren (string)  o searchLogic (string)  o instanceNumber (number stored as a string)  o EITHER hierarchyValue (string) OR hierarchyAttributeID (string)* The only other optional fields are the following:  o subsetAssetType (string)  o queryAssetIDFromThisAttribID (string)* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="getConn"* parentsOrChildren MUST BE “parents” or “children”* searchLogic must be “oldest” or “newest”* instanceNumber must be integer >0* Only one of (hierarchyValue OR hierarchyAttributeID) can be provided* If hierarchyValue is populated then it must match a hierarchyName in hierarchyList* If hierarchyAttributeID is populated, then assetType/hierarchyAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* If subsetAssetType is provided, then it must match an assetType in assetTypes.json* If queryAssetIDFromThisAttribID is populated, then assetType/queryAssetIDFromThisAttribID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json-----
derivedAttributeDetails_getValue.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAssetType (string)  o targetAttributeID (string)  o targetAttributeMetric (string)  o navMethod (string)  o If navMethod=’knownAssetID’, then attribIDContainingKnownAssetID (string) is required  o if navMethod=’navigate’, then all of the following fields are required… chkThisAssetYN (string), maxUpTrav (number stored as string), exactUpYN (string), maxDownTrav (number stored as string), exactDownTrav (string) and EITHER hierarchyValue (string) OR hierarchyAttributeID (string)* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="getValue"* targetAssetType must match an assetType in assetTypes.json* targetAssetType/targetAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json)* targetAttributeMetric must be one of these values - “currentValue”, “lastValue”, “lastTime”, “assetID”, “assetLabel”* navMethod must be one of these values - “navigate” or “knownAssetID”* If navMethod=knownAssetID then assetType/attribIDContainingKnownAssetID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* if navMethod=’navigate’, then the user must provide valid values for chkThisAssetYN (Y or N), maxUpTrav (integer >=0), exactUpYN (Y or N), maxDownTrav (integer >=0), exactDownTrav (Y or N) AND EITHER hierarchyValue (must match a hierarchyName in hierarchyList.json) or hierarchyAttributeID (assetType/hierarchyAttributeID must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json)-----
derivedAttributeDetails_searchEvents.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o assetType (string)   o attributeID (string)   o targetAttributeID (string)  o oldTimePeriod (number stored as text)  o recentTimePeriod (number stored as text)  o maxEventsToSearch (number stored as text)  o searchLogic (string)  o returnValue (string)* The only other optional fields are  o instanceNumber (number stored as text)  o attribIDContainingKnownAssetID  (string)  o searchSubsetValue (string)  o searchSubsetAttributeID (string)* Derived attribute (assetType/attributeID) must match an assetType/attributeID in derivedAttributes.json with attributeType="searchEvents"* The assetType/targetAttributeID must exist as an assetType/attributeID in the attributes.json (not in derivedAttributes)* If attribIDContainingKnownAssetID is specified, then assetType/attribIDContainingKnownAssetID must match as assetType/attributeID in either attributes.json or derivedAttributes.json* oldTimePeriod and recentTimePeriod must be integers greater than or equal to 0* oldTimePeriod must be greater than recentTimePeriod* maxEventsToSearch must be an integer greater than 0* searchLogic must be one of the following:  oldest, newest, min, max, avg, sum* returnValue must be one of the following: value or time* if returnLogic is ‘oldest’ or ‘newest’, then the user must also specify an instanceNumber. If specified, instanceNumber must be an integer >0. ‘1’ means to obtain the oldest/newest, ‘2’ means to obtain the 2nd oldest/newest, etc.* returnValue must be ‘value’ if returnLogic in (min, max, avg, sum). returnValue can be ‘value’ or ‘time’ if returnLogic in (oldest, newest)-----
userDefinedCode.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o SASAttributeID (string)   o attributes – this should contain a nested array, with each record containing two fields    * assetType (string)     * attributeID (string)   o logic (string)* The only other optional fields are the following:  o <None>* Must match a SASAttributeID  in derivedAttributes.json with attributeType="code"* The field logic must contain valid SAS code. Since the code is stored in a json field, these characters need to be escaped – double-quote, backslash, newline, and tab* Any attribute mentioned in the SAS code in the ‘logic’ tag MUST BE listed as an attribute in the ‘attributes’ tag. The ‘attributes’ tag MUST BE a nested array of {“assetType:”myAssetTypeHere”, “attributeID”: “myAttributeIDHere”} entries* All attributes in the nested array must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* No ambiguous attributes from multi-parent/multi-child scenarios* The structure of this json file MUST ALWAYS STRICTLY FOLLOW the format of the example json shown below…[            {                "SASAttributeID": "currentPerIrradiance",                "logic": "currentPerIrradiance = current_allStrings / irradiance_poa_myPV;",              "attributes": [      		 { "assetType": " solarFarm ", "attributeID": "current_allStrings" },  		 { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" }	                  ]            }        ]-----
outputDefinitions.json* Confirm that all required fields are included and contain the correct data type (numeric/string)…  o outputTableAssetType (string)   o attributes – this should contain a nested array, with each record containing two fields    * assetType (string)     * attributeID (string) * The only other optional fields are the following:  o <None>* outputTableAssetType must match an assetType in assetTypes.json* Each record lists attributes as a nested array of {“assetType:”myAssetTypeHere”, “attributeID”: “myAttributeIDHere”} entries* All attributes in the nested array must match an assetType/attributeID in attributes.json or must match an assetType/attributeID in derivedAttributes.json* No ambiguous attributes from multi-parent/multi-child scenarios* The structure of this json file MUST ALWAYS STRICTLY FOLLOW the format of the example json shown below…[  {    "outputTableAssetType": "inverter",    "attributes": [      { "assetType": "inverter", "attributeID": "inv_current_sum" },      { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" }    ]  },  {    "outputTableAssetType": "string",    "attributes": [      { "assetType": "string", "attributeID": "current_A" },      { "assetType": "solarFarm", "attributeID": "irradiance_poa_myPV" },      { "assetType": "combinerBox", "attributeID": "CMBX_temperature_C" }    ]  }]-----
